# Pin subagent tiers natively, let the proxy watch

The most reliable way to make Claude Code v2.1.32x use different models for different work is static native configuration. Pin `model:` and `effort:` in `.claude/agents/*.md` files, shadow the built-in `Explore` agent with a Haiku version, and leave the main conversation's model to the user (`/model`, `opusplan`). A local proxy at `ANTHROPIC_BASE_URL` should mostly observe and enforce at the edges, not reroute the main loop turn by turn. Three facts drive this. First, no hook can choose the main session's model. Hooks can only add advisory context, veto a user's switch, or attempt a PreToolUse rewrite of the `Agent` call, and bug reports dispute whether that rewrite works. Second, CLAUDE.md delegation rules are explicitly "context, not enforced configuration", and one measured dataset recorded zero unprompted subagent spawns in 576 headless runs. Third, Claude Code keeps a separate prompt cache per model, so each silent main-loop model switch re-bills the whole conversation at cache-write rates. On a 150K-token context, moving from Opus 5.5 to Sonnet 5.5 costs about $0.375 in cache writes, where staying on Opus would have cost a $0.03 cache read. Measured savings from tiering are real but modest. Anthropic's own evals show Haiku subagents under Opus cutting cost 32% for a 4-point quality loss, and Opus with Sonnet workers matching Opus alone at about a third less cost, but only on large, parallel work. A proxy is legitimate and well specified with your own API key. Routing a Pro/Max subscription through a personal local proxy is not explicitly forbidden or permitted: the gateway docs describe the mechanism neutrally, but the November 2026 Usage Policy and the OAuth rules mark out the lines a proxy must not cross. The hybrid that works divides the job by layer. Native config owns who does what. A prompt classifier in a hook owns advice. The proxy owns stickiness, telemetry, auxiliary traffic and a backstop for subagents that slip through.

## Native configuration resolves models through four ranked orders

Claude Code has separate precedence chains for the main loop, for subagents, for effort and for skills. A routing design has to know which one it is acting on. The main conversation's model is resolved as `/model` > `--model` > `ANTHROPIC_MODEL` > the settings `"model"` field > `ANTHROPIC_DEFAULT_MODEL` (v2.1.236+) > the account default. That default is **Opus 5.5 on Pro, Max, Ultra, Team, Enterprise and the Anthropic API** ([Model config](https://code.claude.com/docs/en/model-config)). The `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` variables remap the aliases to full IDs. The Haiku variable also sets the model for "background functionality", and it replaces the deprecated `ANTHROPIC_SMALL_FAST_MODEL` ([Model config](https://code.claude.com/docs/en/model-config); [Env vars](https://code.claude.com/docs/en/env-vars)). `opusplan` is the only native alias that switches by work phase: Opus in plan mode, Sonnet for execution ([Model config](https://code.claude.com/docs/en/model-config)).

Subagents follow their own order. **The per-invocation `model` parameter on the Agent tool comes first, then the definition's `model:` frontmatter (where `inherit` means the main model), then `CLAUDE_CODE_SUBAGENT_MODEL`, then the main conversation's model** ([Sub-agents](https://code.claude.com/docs/en/sub-agents)). The per-call parameter accepts only the aliases `sonnet`, `opus`, `haiku` and `fable`, not full IDs or `inherit`, so pinning exact versions means remapping the aliases through the `ANTHROPIC_DEFAULT_*_MODEL` variables. Since v2.1.251, `CLAUDE_CODE_SUBAGENT_MODEL` is a default rather than an override. Setting `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` (v2.1.257+) makes it absolute: frontmatter is then ignored and Claude cannot pass a model per call ([Env vars](https://code.claude.com/docs/en/env-vars)). Several things sit above or across this chain. A mod's `agent.spawn` hook replaces the per-call parameter. `availableModels` allowlists can step a blocked alias down to the newest permitted version. A family alias resolves to the main model's exact ID, `[1m]` suffix included, when the main model is already in that family ([Sub-agents](https://code.claude.com/docs/en/sub-agents)). Use `/tasks` to check which model and effort each subagent actually ran on (v2.1.243+) ([Sub-agents](https://code.claude.com/docs/en/sub-agents)).

The built-in subagents defeat the most common assumption. **Explore, Plan and general-purpose all inherit the main model.** Explore has one exception: on a subscription, Console account or `ANTHROPIC_BASE_URL` gateway, it runs on Opus when the main model is Fable ([Sub-agents](https://code.claude.com/docs/en/sub-agents)). Explore therefore no longer defaults to Haiku. "Setting only `CLAUDE_CODE_SUBAGENT_MODEL` doesn't change the Explore or Plan models". The documented way to put exploration on Haiku is a project or user agent named `Explore` with `model: haiku`, which outranks the built-in on a name clash ([Sub-agents](https://code.claude.com/docs/en/sub-agents)). This is the cheapest deterministic lever available, and it needs no hook or proxy.

Effort has its own chain, and its top entry is a trap. **`CLAUDE_CODE_EFFORT_LEVEL` beats everything**: the in-session pick, `--effort`, settings, agent frontmatter `effort`, skill `effort`, and the Agent tool's per-call `effort` parameter (v2.1.292+) ([Model config](https://code.claude.com/docs/en/model-config); [Sub-agents](https://code.claude.com/docs/en/sub-agents)). Setting it globally silently flattens all per-agent effort tuning. Also, a subagent on a different model from the main loop does not inherit the session effort. Since v2.1.317 it uses that model's saved level or default, so "to pick a subagent's level, set `effort` in its definition" ([Model config](https://code.claude.com/docs/en/model-config); [Changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). `ultrathink` is the only remaining per-turn keyword. "think hard" and similar phrases are passed through as ordinary text ([Model config](https://code.claude.com/docs/en/model-config)).

Skills add a fourth path. A skill's `model:` without `context: fork` switches the main loop "for the rest of the current turn" and then reverts. That is a real model switch, with the cache cost that implies. With `context: fork`, `model` and `effort` instead configure the forked subagent, which runs in the background by default since v2.1.218 ([Skills](https://code.claude.com/docs/en/skills); [Changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). Output styles cannot set a model or effort ([Output styles](https://code.claude.com/docs/en/output-styles)).

| Lever | Scope | Deterministic? | Overridden by |
|---|---|---|---|
| Agent frontmatter `model:` / `effort:` | One subagent type | Yes, once that agent is chosen | Per-call `model`/`effort`, `_FORCE`, `CLAUDE_CODE_EFFORT_LEVEL`, mods |
| Custom `Explore` with `model: haiku` | All exploration | Yes | Nothing native besides `_FORCE` |
| `CLAUDE_CODE_SUBAGENT_MODEL` | Unassigned subagents | Yes (default only) | Per-call, frontmatter |
| `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` | All subagents except `inherit` forks | Yes | Nothing |
| Agent tool `model` / `effort` param | One spawn | The model decides whether to pass it | `_FORCE`, mods, `CLAUDE_CODE_EFFORT_LEVEL` |
| `opusplan` | Main loop by plan mode | Yes | `/model` |
| Skill `model:` (no fork) | Rest of one turn | Yes, if the skill fires | Allowlist, auto mode |
| CLAUDE.md / hook `additionalContext` | Advice to the main agent | No | Model judgment |

### Hooks can advise, veto and possibly rewrite, but never pick the main model

No documented hook output sets the session's model, effort or thinking. Hooks can read effort (the `effort.level` input, `$CLAUDE_EFFORT`), but it is "input only". The `model` field appears only on SessionStart, and "Claude Code doesn't always include it" ([Hooks](https://code.claude.com/docs/en/hooks)). PreModelSwitch (v2.1.251+) fires only on user- or SDK-requested switches. It can allow, deny or ask, and it receives useful inputs such as `prompt_cache_warm` and `estimated_cache_write_usd`. It "doesn't accept `"defer"`, `updatedInput`, or `additionalContext`", so it cannot redirect a switch. PostModelSwitch cannot block, but it can inject guidance with the next request. The docs' own example is "On Opus, delegate implementation work to subagents" ([Hooks](https://code.claude.com/docs/en/hooks)). SubagentStart can inject context into a subagent but cannot change its model. Requests to add that ability (#95769, open since September 2026) have no maintainer response ([Issue #95769](https://github.com/anthropics/claude-code/issues/95769)).

That leaves **PreToolUse `updatedInput` on the `Agent` tool as the only mechanical hook lever, and it is unverified**. On paper `updatedInput` replaces the whole tool input, and the Agent input includes an optional `model` alias ([Hooks](https://code.claude.com/docs/en/hooks)). In practice, #39814 (v2.1.85+) reports the subagent receiving the original prompt despite a valid rewrite, and #44412 reports a `model: "sonnet"` rewrite being ignored. Both were closed by a bot with no fix version ([Issue #39814](https://github.com/anthropics/claude-code/issues/39814); [Issue #44412](https://github.com/anthropics/claude-code/issues/44412)). The September 2026 counter-report says the rewrite works with matcher `"Task"` but that `"Agent"` never fires. This contradicts the current docs, which name the tool `Agent` ([Issue #95769](https://github.com/anthropics/claude-code/issues/95769)). Related reports describe `updatedInput` failing with multiple PreToolUse hooks and in `-p` mode ([Issue #15897](https://github.com/anthropics/claude-code/issues/15897)). UserPromptSubmit cannot replace the prompt. It can add `additionalContext`, which is wrapped in a `<system-reminder>` and placed "alongside the submitted prompt" at the tail of the conversation. That placement leaves the cached prefix intact, but the hint is purely advisory. A classifier that exceeds the 30-second timeout is silently dropped unless `onFailure: "block"` is set ([Hooks](https://code.claude.com/docs/en/hooks)).

## Delegation instructions are soft priors, and tiering saves less than price sheets imply

Anthropic does not claim CLAUDE.md is binding. The memory docs say Claude treats it "as context, not enforced configuration", that there is "no guarantee of strict compliance, especially for vague or conflicting instructions", and that files over about 200 lines "reduce adherence". To block an action regardless of what Claude decides, they point to a PreToolUse hook ([Memory](https://code.claude.com/docs/en/memory)). The best-practices page adds that writing "IMPORTANT" won't fix an ignored line. The line is either lost in a long file or "a rule that can't have exceptions, in which case it belongs in a hook". It also notes that even `prompt`/`agent` hooks are non-deterministic because they ask another model ([Best practices](https://code.claude.com/docs/en/best-practices)). Delegation depends on the request, the subagent `description` (where "use proactively" phrasing is encouraged) and the current context ([Sub-agents](https://code.claude.com/docs/en/sub-agents)).

The field evidence is weak in both directions but points one way. In #70268, the CLAUDE.md said "use haiku agents with WebSearch" and the user repeated the instruction, yet the agent answered from its own knowledge until asked again ([Issue #70268](https://github.com/anthropics/claude-code/issues/70268)). In #47598, a user with eight custom agents and a delegation table reports Claude "Ignores the CLAUDE.md delegation table entirely" ([Issue #47598](https://github.com/anthropics/claude-code/issues/47598)). The only counted data comes from a single-author experiment on Claude Code 2.1.318 headless: **Claude Code never spawned a subagent unprompted, 0 of 72 runs and 0 of 504 in an earlier dataset**. When told to use subagents for code search, cost rose **74–116% on Haiku 5.5 and 143–221% on Opus 5.5**, recall stayed within about 2 points, and runs took 2–3× longer ([dev.to](https://dev.to/jaehyun_cho_0dff271e0d2e5/i-told-claude-code-to-use-subagents-216-times-it-found-nothing-more-and-cost-up-to-221-more-14ea)). Both models were near ceiling and only one prompt wording was tested, so this shows that forced delegation of small tasks wastes money. It does not show that tiering never pays.

Anthropic's own measurements are better controlled and more nuanced. Adding Haiku 5.5 subagents to Opus 5.5 at `medium` with a short delegation prompt **cut cost per attempt by 32% while pass rate fell about 4 points (95% CI 1.3–7.1)**. Anthropic calls that "about what a mix of `low` and `medium` without subagents would give". On a large defect-search task, **Opus 5.5 with Sonnet 5.5 subagents scored F1 0.831 for $139, against 0.827 for $200 with Opus alone**. For "one dependent chain, or work that fits in one context", the single model at lower effort "came out ahead in every case measured" ([Optimizing for cost and intelligence](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)). Anthropic's multi-agent research post explains the mechanism: multi-agent systems use about **15× the tokens of chat**, and token usage explains 80% of performance variance on BrowseComp ([Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)). The "50–90% cheaper" claims in blog posts mostly multiply list-price ratios rather than measure tasks ([wmedia.es](https://wmedia.es/en/tips/claude-code-haiku-5-5-subagents)). Tiering pays when the delegated work is independent, parallel or too large for one context. It loses when it splits a dependent chain, because every fresh subagent must re-gather context the parent already had.

## Every model switch rebuilds the cache, and thinking stays with its model

Claude Code's caching doc is unambiguous: **"each model has its own cache. Switching models recomputes the entire request even when the content is identical."** Two requests share a cache only when "model, speed, and prefix match" ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). Cache writes cost 1.25× base input at a 5-minute TTL and 2× at 1 hour. Reads cost 0.05× on Opus 5.5 and Sonnet 5.5, and 0.025× on Fable 5.2 ([Prompt caching API](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). On a subscription within plan usage, the main conversation gets a 1-hour TTL and subagents, forks, compaction and titles get 5 minutes. API keys get 5 minutes everywhere ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). On a 150K-token context with an API key, a single Opus 5.5 → Sonnet 5.5 switch costs about $0.375 in Sonnet cache writes, against a $0.03 Opus cache read. Switching back costs another $0.75 unless the old Opus entry is still within its TTL. These figures are my arithmetic from the published prices ([Pricing](https://platform.claude.com/docs/en/about-claude/pricing)). **A proxy that ping-pongs the main loop per turn can cost more than leaving it on Opus.** On a subscription, the 1-hour TTL doubles the write cost in usage-limit terms. Claude Code itself confirms `/model` switches only while the cache is warm, which shows the cost is real enough for the product to warn about ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)).

Subagents are where switching is cheap. A subagent "starts its own conversation with its own system prompt and tool set". Its first request cannot read the parent's cache anyway, spawning it is listed among "actions that keep the cache", and "the parent's cache is unaffected" ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). A **fork** is the exception. It inherits the parent's prefix exactly and reads the parent's cache, so routing a fork to a different model throws away a free cache read. Effort changes are mostly safe on the current generation. With an API key or subscription on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1+, Claude Code sends per-turn effort through `role: "system"` entries plus a beta header, and the cache survives. A gateway that strips the header or entries gets a 400 ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching); [Gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)).

Thinking blocks do not break a model switch, but they do not carry across tiers either. On the Claude API, "a thinking block that the new model or account can't use never causes an error. The API drops it for that request and doesn't bill it". The docs name routers explicitly: "Keep sending the whole conversation... don't keep a separate history for each model" ([Preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)). The cross-read matrix matters for downgrades: **Opus 5.5 blocks are unreadable by Sonnet 5.5 and Haiku 5.5**, so a downgraded turn reasons without its predecessor's chain of thought. The hard constraint is the preserved-thinking prefix check. It fails if `system`, `tools` or any earlier message changed after a block was produced, and changing `model` or `effort` does not count ([Prefix checks](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/prefix-checks)). A proxy that injects routing text into `system`, trims history or reorders blocks causes `400 ... bound to a different conversation`. Claude Code then responds by stripping earlier thinking blocks "and keeps them out of every later request" ([Gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)). **The proxy may rewrite the `model` string and nothing else in the body.**

## Gateways must forward almost everything, and billing follows the credential

The gateway contract is strict and open-list. Speak the Anthropic Messages format (`/v1/messages`, plus optional `count_tokens`). Forward `anthropic-version` and `anthropic-beta` "verbatim; don't allowlist individual values". Pass all `anthropic-*` headers and body fields through unchanged. Return error bodies unmodified so Claude Code's capability recovery can match them. Pass back `anthropic-ratelimit-unified-*` headers so plan limits display correctly ([Gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)). Claude Code prepends a system attribution block containing a conversation fingerprint, and api.anthropic.com strips it only "when it arrives unchanged as the first system block". Reordering or stringifying `system` leaks it into the model's context and the cache key ([Gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)). Silently removing `cache_control` markers makes "your entire conversation history bill as uncached input on every turn" ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). For routing, the most useful feature is the hint headers enabled by `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` (v2.1.273+). **`x-claude-code-request-class` (`main`, `subagent`, `workflow`, `compaction`, `auxiliary`), `x-claude-code-agent-type` (including `fork`) and `x-claude-code-agent-id`** let the proxy classify traffic without parsing prompts ([Gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)). Claude Code builds each request for the model it believes it is calling. For an ID it does not recognize, it sends every current feature and assumes a 200K window. So a proxy that swaps in a model with a different capability set risks 400s, after which Claude Code degrades features for the rest of the process ([Gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol)). Swapping within the 5.5 generation avoids most of these mismatches.

Billing is set by the credential, not by the URL. "Setting only [`ANTHROPIC_BASE_URL`], without a gateway credential, doesn't replace the subscription", and gateways that pass this traffic to Anthropic "must forward `Authorization` and the OAuth capability in `anthropic-beta`". Once `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY` or `apiKeyHelper` is active, "the subscription's usage limits don't apply" and traffic "is billed per token to whoever owns the credential" ([LLM gateway](https://code.claude.com/docs/en/llm-gateway)). In `-p` mode a present `ANTHROPIC_API_KEY` is always used, so a stray key in the environment silently moves you to API billing ([Authentication](https://code.claude.com/docs/en/authentication)).

On permission, the API-key case is explicitly fine. Customers may configure their own key for "the customer's own authorized users — provided the resulting usage is billed to the key owner... and is not resold or intermediated" ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). **The subscription case is not addressed by any rule.** The gateway docs describe base-URL-plus-OAuth neutrally and tell gateways how to forward the bearer, which is strong implicit evidence that the configuration is expected ([LLM gateway](https://code.claude.com/docs/en/llm-gateway)). Against that, OAuth "is designed to support ordinary use of Claude Code and other native Anthropic applications". Developers "may not collect, store, or intermediate Claude.ai credentials or session tokens", though the rules do not prevent "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription" ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). The Usage Policy effective 12 November 2026 forbids providing access "through unauthorized means, including services that route requests through consumer subscriptions or misrepresent the product or client being used" ([Usage Policy](https://www.anthropic.com/legal/aup)). The Consumer Terms bar account sharing and "bypassing any of our systems or protective measures" ([Consumer Terms](https://www.anthropic.com/legal/consumer-terms)). In February 2026, Anthropic staff called third-party harnesses on subscriptions "prohibited by our Terms of Service" ([The Register](https://www.theregister.com/2026/02/20/anthropic_clarifies_ban_third_party_claude_access)). My reading is that a personal, loopback-only, pass-through proxy in front of the unmodified binary is gray territory, and it moves toward prohibited as soon as it serves anyone else, accepts non-Claude-Code clients, logs or stores the bearer, alters the attribution block, or stretches usage beyond "ordinary, individual usage". Anthropic reserves enforcement "without prior notice", and a model rewrite under OAuth also spends Opus-specific limits the user never chose.

## Haiku searches, Sonnet implements, Opus decides, Fable takes the ambiguous

Price and capability gaps are not proportional, and that shapes the tiers. Per MTok, Haiku 5.5 costs **$0.10/$0.50 for prompts up to 100K tokens but $0.50/$2.50 above**, Sonnet 5.5 $2/$10, Opus 5.5 $4/$20, and Fable 5.2 $8/$40. Cache reads compress the spread: Opus and Fable both read at $0.20 ([Pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Haiku 5.5's tokenizer also produces about 30% more tokens than Haiku 4.5 for the same text ([Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/whats-new-haiku-5-5)). Haiku is therefore cheap only on short, fresh contexts, which is exactly what an exploration subagent has and a long main loop does not. On capability, the largest cliff is Haiku → Sonnet. Haiku 5.5 reports 39.2% on Terminal-Bench 4.0 against Sonnet 5.5's 70.6% ([officechai](https://officechai.com/ai/claude-5-5-haiku-benchmarks/); [Anthropic Sonnet 5.5](https://www.anthropic.com/claude-sonnet-5-5)). Sonnet roughly ties or beats Opus on terminal work (63.6% vs 59.6% in Artificial Analysis's independent run) but trails on FrontierCode and repo tasks ([mixed-news](https://mixed-news.com/en/claude-sonnet-5-5-terminal-bench-70-6-percent-half-opus-price/)). On Anthropic's internal repo tasks, **Sonnet 5.5 at default scored about 9 points below Opus 5.5 at default for about two-fifths of the cost** ([Optimizing for cost and intelligence](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)).

Anthropic's positioning matches the data. Haiku 5.5 is for "classification, routing, extraction, and subagent tasks" with "checkable outputs". Sonnet 5.5 is for "daily coding" and well-scoped bug fixes, and is recommended for agent teammates. Opus 5.5 at `medium` is the default for most workloads. Fable 5.2 is for "ambiguous problems" such as root-cause investigations, outage debugging and architecture decisions, or for cases where Opus at `xhigh` still fails ([Models overview](https://platform.claude.com/docs/en/about-claude/models/overview); [Choosing a model](https://platform.claude.com/docs/en/about-claude/models/choosing-a-model); [Costs](https://code.claude.com/docs/en/costs); [Model config](https://code.claude.com/docs/en/model-config)). Claude Code defaults all four to `medium`. It maps `low` to small reviewed changes and renames, `medium` to clearly scoped features, `high` to bug fixes where verification matters, `xhigh` to long runs, and `max` sparingly to hard autonomous work such as security audits ([Model config](https://code.claude.com/docs/en/model-config)). Haiku at `low` on long agent prompts "is more likely to skip a search, stop early, or skip a check" ([Effort](https://platform.claude.com/docs/en/build-with-claude/effort)).

Effort often beats switching tiers. Anthropic says outright that "tuning effort is often a better lever than switching models" ([Choosing a model](https://platform.claude.com/docs/en/about-claude/models/choosing-a-model)). There is no general rule between a strong model at low effort and a weak model at high effort. Sonnet `high` (77.8%, $0.33) beat Opus `low` (74.8%, $0.35) on repo tasks. Fable `low` (88.9%, $1.05) edged out Opus `high` (88.4%, $1.38). On a 22M-token defect search, Opus `low` collapsed below Haiku. The single best measured policy was **escalation on failure: Opus 5.5 `low` with failures re-run at `high` solved about 97% for $0.17 per task, against 95.3% for $0.29 with everything at `high`**. It works only with a checker that catches bad work ([Optimizing for cost and intelligence](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)).

## Design recommendations: which layer owns which decision

The table assigns ownership. The prose after it orders the work by expected payoff and risk.

| Decision | Owner | Why |
|---|---|---|
| Which model each subagent type runs | Native frontmatter | Deterministic, cache-neutral, visible in `/tasks` |
| Exploration on Haiku | Native custom `Explore` agent | The built-in inherits Opus; no hook is needed |
| Main-loop model and phase switching | User via `/model` or `opusplan` | No hook can set it; silent switches rebuild the cache |
| Per-agent effort | Native frontmatter `effort:` | Session effort does not reach cross-model subagents |
| "Should this prompt be delegated?" | UserPromptSubmit classifier hint | Advisory, cache-safe, fails open |
| Forcing a per-spawn model | PreToolUse `Agent\|Task` rewrite, if self-tested | Only mechanical hook lever; reliability disputed |
| Sticky model per subagent ID, aux/title traffic, telemetry | Proxy | Sees every request class through hint headers |
| Guarding expensive warm-cache switches | PreModelSwitch hook | Gets `estimated_cache_write_usd` and can ask or deny |

**First, build the static native layer and measure it before adding anything else.** Create `.claude/agents/Explore.md` with `model: haiku` and `effort: medium`. Add an implementer agent on `sonnet` at `medium`, a bug-fix agent on `sonnet` at `high`, and a planner/reviewer on `opus` at `medium`. Write action-oriented descriptions with "use proactively" phrasing. Set `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` without `_FORCE`, so unassigned and general-purpose agents drop off Opus while Claude can still escalate per call. Pin `ANTHROPIC_DEFAULT_*_MODEL` to full 5.5 IDs so alias behaviour cannot drift by provider. Do not set `CLAUDE_CODE_EFFORT_LEVEL`, because it overrides every per-agent effort. This layer captures the documented savings (Explore off Opus, Sonnet workers) with no reliability or compliance risk, and it is the layer Anthropic's own −32% and −⅓ measurements correspond to.

**Second, leave the main loop's model to the user.** Default to Opus 5.5 at `medium`, or `opusplan` for plan-heavy work. If a proxy chooses the main model at all, it should decide once, at the first `main` request of a session (keyed on `x-claude-code-session-id`), and never change it mid-session. Even that is risky. Claude Code's request shape, context-window assumption and `/usage` accounting all assume the model it chose, and a Haiku main loop pays the over-100K surcharge in long sessions.

**Third, use hooks for advice and guarded enforcement.** A fast prompt classifier (for example a simple/mid/complex tier model) belongs in UserPromptSubmit. It emits a short `additionalContext` such as "simple: answer directly" or "complex: plan, then delegate implementation to the implementer agent". Keep it well under the 30-second timeout and let it fail open. Add a PreToolUse hook with matcher `Agent|Task` that rewrites only the `model` alias, copies every other field, and returns `permissionDecision: "allow"`. Run a startup self-test that spawns a known agent and checks the resulting model in `agent_transcript_path` or `/tasks`, and disable the rewrite loudly if it is ignored. A PreModelSwitch hook can ask before any switch whose `estimated_cache_write_usd` crosses a threshold.

**Fourth, make the proxy a transparent observer with narrow powers.** Enable `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`. Forward headers, the `system` array, `cache_control`, error bodies and rate-limit headers byte-for-byte, and rewrite only the `model` string. Keep forks on the parent's model. Keep each `x-claude-code-agent-id` on one model for its lifetime. Route `auxiliary` traffic to Haiku only after measuring the effect. Leave `compaction` on the main model unless measurement shows otherwise, because it can read the main cache. The proxy's main value is the per-request ledger of model, cache reads/writes and request class that no native surface provides, since the `/usage` cache line covers only the main conversation ([Costs](https://code.claude.com/docs/en/costs)).

**Fifth, put escalation where there is a checker.** For tasks with tests, start at `low` or `medium` and re-run failures at `high` or on the next tier. Escalation, not static tiering, produced Anthropic's best measured cost per solved task. **Sixth, default the proxy to API-key mode.** Make OAuth pass-through an explicit, warned opt-in that binds to loopback only, never logs `Authorization`, accepts only Claude Code traffic, and leaves the attribution block untouched.

## Conclusion

The idea of "a router in front of Claude Code" assumes the model choice is made in one place. It is actually split across four precedence chains, a cache keyed on model, and a thinking format bound to its model. That split makes per-request main-loop routing the most expensive place to optimize, and subagent boundaries the cheapest, because they already start fresh caches and already carry a native `model:` field. The proxy's most defensible role is not deciding the model but showing whether native routing works: which agent ran on which model, at what cache cost, and whether the delegation hint changed anything.

The evidence also changes the goal. Anthropic's data shows tiering gains of about a third at best, often matched by simply lowering effort. Its biggest measured win came from escalating on failure, which needs a pass/fail signal more than a better classifier. A tier classifier earns its place when it decides how hard to try first and when to retry harder, not when it swaps models turn by turn. The compliance boundary on subscriptions is unsettled and enforced without notice, so any proxy meant for other people should treat API-key mode as the product and OAuth pass-through as a personal, opt-in convenience.
