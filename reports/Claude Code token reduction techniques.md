# Shrink what every turn re-reads first

Beyond model routing, the techniques that reliably cut Claude Code cost are the ones that shrink or protect what every request re-reads. That means trimming the user-controlled static prefix, keeping the prompt cache from being rebuilt, capping how large the conversation is allowed to grow before compaction, and keeping effort at the 5.5-generation default of `medium`. Each of these can be done from settings, hooks, skills and output styles, and none needs a proxy. Aggressive tool-output compression, the technique most token-saving tools promote, has the weakest cost record. A 2,848-run billed study found that a 38.4% cut in tool-output tokens *raised* cost 6.8%. Three independent A/B tests of RTK found cost changes of −0% to +17%. Both failures trace to extra turns and to cache reads being cheap ([arXiv 2607.12161](https://arxiv.org/abs/2607.12161); [horadecodar](https://horadecodar.com.br/?p=48327)). On Opus 5.5 and Sonnet 5.5, cache reads cost 0.05× input, so cache *writes* and *output* (including thinking) carry a larger share of the bill than on older models. In one local Opus 5.5 session the split was roughly a third each for reads, writes and output. That shifts priority toward avoiding cache rebuilds and controlling effort, and away from squeezing bytes. For adtok, the result is six ensemble layers behind one hook dispatcher: measure, prefix, cache, tools, context and output, alongside the existing routing layer. A conflict check enforces the one rule every layer must obey: change only what enters the conversation for the first time, and never what is already cached. The measurement layer has to judge everything by cost per successful task, not tokens removed. The evidence shows those two metrics barely correlate (Pearson r = 0.15).

## Cache reads and writes, not tool bytes, set the bill

The economics decide the order of the work, so they come first. Claude Code lays every request out as tools and system prompt, then project context (CLAUDE.md, auto memory, unscoped rules), then the conversation. There is "no per-file or per-segment caching", so an early change rebuilds everything after it ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). On list prices, Opus 5.5 is **$4 input, $5 5-minute write, $8 1-hour write, $0.20 cache read and $20 output per MTok**. Sonnet 5.5 is exactly half that. Haiku 5.5 is $0.10/$0.50 up to a 100K-token prompt and five times that above it ([Pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Thinking is billed as output, and on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable it cannot be turned off ([Manage costs](https://code.claude.com/docs/en/costs)).

The documented `/usage` example (Sonnet 4.6: 1.2k input, 5.3k output, 940k cache read, 50k cache write, $0.55) works out to about **51% cache reads, 34% cache writes and 14% output** ([Manage costs](https://code.claude.com/docs/en/costs)). A deduplicated local Opus 5.5 transcript on this machine (138 input, 66,625 output of which 18,605 thinking, 6.8M cache read, 150k 1-hour write) priced at the published rates gives **$1.36 reads, $1.20 writes and $1.33 output**. That equals Claude Code's own recorded `costUSD` of $3.898 to the cent ([Pricing](https://platform.claude.com/docs/en/about-claude/pricing); [Agent SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)). This is one session, not a dataset, but it shows the structural point. At 0.05× reads, **a token that enters context early is cheap to keep, and expensive to write or rewrite**. Output, much of which is tool-call arguments such as Edit and Write bodies rather than prose, is a third of the bill, not the 0.6–3% that visible-text estimates suggest ([Implicator](https://www.implicator.ai/caveman-claude-code-skill-cuts-output-20-your-bill-barely-notices-2.md)).

The same arithmetic explains why output-compression tools lose money. A 20K-token test log that enters at request 10 of a 100-request Opus 5.5 session costs about $0.16 to write (1-hour TTL) and $0.36 in re-reads, about $0.52 in all. Trimming it to 1K saves roughly $0.49. One extra turn at 150K context costs roughly $0.03 in reads plus $0.04 for 2K output tokens. So trimming a large log pays even if it costs a turn. Trimming a 2K-token `git status` saves about $0.03, and a single recovery turn wipes that out. These figures are my arithmetic from the price sheet. They match the evidence that blanket filters such as RTK save bytes and lose dollars, and they argue for **size thresholds rather than blanket compression** ([rtk-ai/rtk](https://github.com/rtk-ai/rtk); [horadecodar](https://horadecodar.com.br/?p=48327)). PointFive's paper names the same mechanism: cache creation and reads "dominate the measured input-side cost", and aggressive compression reduced successful patch application ([arXiv 2607.12161](https://arxiv.org/abs/2607.12161)).

## A deterministic prefix audit saves on every request

The static prefix is the one cost that is certain. Every token in it is billed on every request at the cache-read rate, written again after each compaction, and written again at the start of every session. Claude Code already ships checkers: length warnings at startup and in `/status`, `/doctor` CLAUDE.md trims, `/doctor prompt-audit` (v2.1.283+), `/usage` recommendation rows such as "Trim ~/code/api/CLAUDE.md · 49k tokens per request", and `/context all` ([Memory](https://code.claude.com/docs/en/memory); [Manage costs](https://code.claude.com/docs/en/costs)). These checks are interactive or LLM-based, and `prompt-audit` spends tokens itself. adtok's gap to fill is an **offline, deterministic byte and token count of every user-controlled prefix component**, with rule-based fixes it can test.

The built-in system prompt and tools are out of reach, and the user-controlled parts are the ones to target. `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=1` selects the shorter prompt, but models newer than Sonnet 5 and Opus 4.7 already use it by default. On the 5.5 generation it saves nothing ([Env vars](https://code.claude.com/docs/en/env-vars)). Secondary readouts put built-in tools at about 12–18K tokens and the system prompt at about 3–6K, but those figures predate the shorter prompt ([dannywillems](https://dannywillems.github.io/2026/01/16/claude-code-context-command.html)). The audit should derive this fixed part as the first turn's `cache_creation_input_tokens` minus the user-controlled parts it counts.

The audit's lint rules follow from the documented limits. It should flag any CLAUDE.md, rules file or import over 200 lines, counting each one separately the way Claude Code does, and flag `@imports` that look like a saving. It should flag unscoped rules whose content names a single directory, on-demand files over 40,000 characters (the 200K-window truncation point since v2.1.309), MEMORY.md past 200 lines or 25KB (the tail is silently dropped, which is a quality problem), skill descriptions over 1,536 characters, and an `outputStyle` value that matches no file, which silently falls back to Default ([Memory](https://code.claude.com/docs/en/memory); [Skills](https://code.claude.com/docs/en/skills); [Output styles](https://code.claude.com/docs/en/output-styles)). A custom output style without `keep-coding-instructions: true` removes the software-engineering section only on the *full* system prompt, so on 5.5 models it is not a prefix lever ([Output styles](https://code.claude.com/docs/en/output-styles)). In money terms the saving is modest. Removing 10K prefix tokens over 200 Opus 5.5 requests saves about $0.40 in reads plus $0.08 per write event, by price-sheet arithmetic. It is certain, though, it compounds across every session and compaction, and it frees context. adtok should also count its own CLAUDE.md block and hook injections in this audit and hold them to a budget.

## Cache hygiene means avoiding nine documented invalidators

The cache is an exact prefix match per model and speed. Claude Code documents what breaks it: switching models (including every `opusplan` plan toggle, a skill or command with a different `model:`, and automatic fallback), changing effort on most models, toggling fast mode, connecting or removing an MCP server, enabling or disabling a plugin, denying an entire tool, compacting, accumulating many images, and upgrading Claude Code ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). Some actions are documented as cache-safe. CLAUDE.md edits do not apply until `/clear`, `/compact` or a restart. Permission-mode changes, output-style switches (applied mid-session since v2.1.251), skill invocations, plugin skills and hooks, `/recap`, `/rewind` and subagent spawns are also safe. Under tool search, a mid-session deny rule leaves the tool definitions unchanged ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). On Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1+, effort changes keep the cache with an API key or subscription. They still break it on Bedrock, Vertex, the apps gateway, under HIPAA, or with `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)).

adtok already guards `/model` switches with PreModelSwitch. Three additions fit the same layer. The first is a **static invalidator lint** that flags the following:

- `opusplan` as the default model
- skills or commands whose `model:` differs from the session model
- `ENABLE_TOOL_SEARCH=false` combined with several MCP servers
- `FORCE_PROMPT_CACHING_5M` left set
- `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`, which also removes tool search, server-side context management and effort cache-safety
- an `ANTHROPIC_BASE_URL` gateway that may strip `anthropic-beta` (1-hour TTL lost) or `cache_control` (the whole history billed "as uncached input on every turn")
- dates or `!`-command output in CLAUDE.md, which hurt cross-session reuse

Sources: [Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching); [LLM gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol).

The second is **cache-miss attribution from transcripts**. Flag any turn whose cache write exceeds a fraction of the previous context, and attribute it to a `message.model` change, a `version` change, a timestamp gap longer than the TTL, or a compaction boundary. `/usage` gives the same "likely cause" (v2.1.260+), but only for the main conversation and only interactively ([Manage costs](https://code.claude.com/docs/en/costs)).

The third is a **TTL advisor**. Subscribers within plan get a 1-hour TTL on the main conversation. API-key, usage-credit and cloud users get 5 minutes. Subagents, forks and compaction get 5 minutes everywhere unless `subagentPromptCacheTtl` is set. The controls are `promptCacheTtl` / `CLAUDE_CODE_PROMPT_CACHE_TTL` and `subagentPromptCacheTtl` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`, taking `"5m"` or `"1h"` (v2.1.242+) ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). A 1-hour write costs 2× input against 1.25× for 5 minutes ([Prompt caching API](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). So the choice depends on how often the user goes idle for 5 to 60 minutes. A rough inference from the multipliers puts break-even near 60% of written prefixes otherwise expiring. Anthropic publishes no figure for this. Rather than state a rule, adtok can re-price a user's real transcripts under both TTLs using their actual inter-request gaps and recommend the cheaper one. The same logic covers two more settings. Leave `idleCompaction` on for subscribers, because it compacts at about 54 minutes, before the 1-hour cache expires (v2.1.299+). Schedule upgrades deliberately (`DISABLE_AUTOUPDATER=1`, then update between sessions), because the first session after an upgrade is uncached ([Settings reference](https://code.claude.com/docs/en/settings-reference); [Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)).

## Tool-output trimming pays only above a size threshold

Claude Code already applies coarse "save full output, show a preview" limits. A successful Bash result stays inline up to about 30,000 characters. Above that, Claude gets a file path and a 2,000-character head preview. A *failed* command stays inline up to about 10,000 characters, and beyond that Claude gets a head-and-tail excerpt **with no file path**. `bashOutputMaxChars` (v2.1.261+, up to 128,000) sets both ceilings. `BASH_MAX_OUTPUT_LENGTH` sizes only the read-back window. Read returns at most 25,000 tokens (`CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS`) unless the model passes `allow_large: true` (v2.1.296+). Glob caps at 100 files. MCP output defaults to `MAX_MCP_OUTPUT_TOKENS=25000`, and any text result over 50,000 characters is spilled to a file ([Tools reference](https://code.claude.com/docs/en/tools-reference); [MCP](https://code.claude.com/docs/en/mcp)). adtok can add value in two places. The first is the 2K–30K band that reaches context in full. The second is failures, which are the largest and most important output, and which built-in persistence handles worst.

The mechanism that is cache-safe and actually works is **PreToolUse `updatedInput`**, because it acts before any output exists. Anthropic's own costs page uses it to rewrite `npm test|pytest|go test` into `… 2>&1 | tail -n 100`, "tens of thousands of tokens to hundreds" ([Manage costs](https://code.claude.com/docs/en/costs)). Its failure modes are well documented. It "replaces the entire input object", so a payload containing only `command` silently dropped a 600-second timeout (#90725). Since v2.1.300 it is schema-validated, and unknown keys are dropped. When two hooks rewrite the same call, "whichever hook finishes last" wins (#83353). In auto mode a rewrite currently forces a refusal and a resend, and invalidates every other call in that response (#109300, open) ([Hooks reference](https://code.claude.com/docs/en/hooks); [#90725](https://github.com/anthropics/claude-code/issues/90725); [#83353](https://github.com/anthropics/claude-code/issues/83353); [#109300](https://github.com/anthropics/claude-code/issues/109300)). Permission rules, including deny rules, are evaluated against the *rewritten* input (#89448) ([#89448](https://github.com/anthropics/claude-code/issues/89448)). A generic wrapper such as `adtok run -- <cmd>` could therefore slip past a `Bash(npm publish*)` deny rule. So adtok should wrap only an allowlist of test, build and lint commands. Its wrapper should tee the full log under the project directory, print the tail plus matched error lines plus "N lines omitted; full log at PATH", and exit with the original status. A shell pipe returns `tail`'s status and breaks Claude Code's failure classification. The hook should merge onto the original `tool_input`, return `"ask"` unless the original command already matched an allow rule, and skip rewriting in auto mode until #109300 is fixed.

**PostToolUse `updatedToolOutput`** (v2.1.121+) is riskier and should be limited to MCP. For built-in tools the value must mirror the tool's native structured shape. A plain string is silently ignored and logged only under `--debug` (maintainer-confirmed in #86753). MCP replacements must be a content-block array, because a malformed object breaks every later call to that tool (#85631) ([#86753](https://github.com/anthropics/claude-code/issues/86753); [#85631](https://github.com/anthropics/claude-code/issues/85631)). **Never truncate Read output after the fact.** The Read dedup cache stores raw content from before the hook ran. On an unchanged re-read, Claude is told it already has content it never received (#88118, open) ([#88118](https://github.com/anthropics/claude-code/issues/88118)). Read is also where compression did its documented damage: it "corrupted literal edit anchors" ([horadecodar](https://horadecodar.com.br/?p=48327)). The safe Read guard adds `limit` only to files above a line threshold when the model gave none, and strips `allow_large`. It does not touch content.

One design rule carries over from Headroom and the proxy work. Compress only content entering the conversation for the first time, and never rewrite earlier messages. Headroom keeps "the frozen prefix … byte-identical" for this reason ([chopratejas/headroom](https://github.com/chopratejas/headroom)). A proxy that compressed earlier tool results would also break the preserved-thinking prefix check. That is why adtok's proxy should stay observe-only.

## Earlier compaction and handoffs cap context growth

The default auto-compaction threshold is now a cost trap. On 1M-native models (Fable, Sonnet 5+, Haiku 5.5, Opus 4.7+), Claude Code compacts "at about 967K tokens by default" ([Model config](https://code.claude.com/docs/en/model-config)). An Opus 5.5 request at 600K context costs about $0.12 in cache reads alone. A 250K ceiling caps that near $0.05. A warm compaction costs roughly one cached read of the context plus a few thousand summary output tokens, so it pays back within a handful of requests. That is my arithmetic. Anthropic says only that a warm `/compact` "costs a fraction of what the context size suggests", while a cold one after the TTL "reprocesses that history as uncached input" ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). The documented controls are the `autoCompactWindow` setting (100,000–1,000,000), `/autocompact 250k` (saved per model since v2.1.288), `--autocompact` per launch, and `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, which beats all of them and accepts `250k` suffixes from v2.1.304. A bare `250` means 250 tokens, clamped to 100K. `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` can only lower the threshold ([Model config](https://code.claude.com/docs/en/model-config); [Env vars](https://code.claude.com/docs/en/env-vars)). This layer also connects to routing. Haiku 5.5 "costs more per token when its prompt is longer than 100K tokens", so adtok's Haiku agent definitions should carry the frontmatter `autoCompactWindow: 100000` (v2.1.296+). It must be a plain integer, because `100k` in frontmatter is read as 100 and ignored ([Model config](https://code.claude.com/docs/en/model-config); [Sub-agents](https://code.claude.com/docs/en/sub-agents)).

The compaction hooks make compaction cheaper and less lossy. PreCompact stdout becomes summary instructions, capped at 10,000 characters. PostCompact receives `compact_summary`. A `SessionStart` hook with matcher `compact` re-injects state afterward ([Hooks reference](https://code.claude.com/docs/en/hooks); [Context window](https://code.claude.com/docs/en/context-window)). adtok can use PreCompact to emit a short project-specific "preserve" list and PostCompact to save the summary to a handoff note. That enables the pattern Anthropic's guidance favours: `/clear`, which "costs nothing", over keeping a compacted session alive when continuity is not needed ([Manage costs](https://code.claude.com/docs/en/costs); [Best practices](https://code.claude.com/docs/en/best-practices)). A hook cannot run `/clear`. adtok can only advise it, for example in the existing UserPromptSubmit hook when context is large and the tier classifier sees a new, unrelated task. `/rewind` truncates back to a prefix that is already cached, so it is the cache-optimal way to abandon a path. Blocking a *recovery* compaction makes the request fail, so adtok should never block compaction by default ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching); [Hooks reference](https://code.claude.com/docs/en/hooks)).

Two other context levers are weaker than often claimed. **Subagents are not a token saver.** Anthropic's best-practices page lists "use subagents to protect your context window" as outdated advice, because a fresh subagent re-gathers context "and can end up *slower*". Agent teams use about 7× the tokens of a standard session ([Best practices](https://code.claude.com/docs/en/best-practices); [Manage costs](https://code.claude.com/docs/en/costs)). Forks read the parent's cache and cost less than fresh subagents ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). The routing layer should keep delegating only independent or verbose work, and keep forks on the parent model. **Server-side context editing** (`clear_tool_uses_20250919`) is sent by Claude Code, but no setting tunes it. The only switch, `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`, turns it off and likely raises tokens ([LLM gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol); [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)). Background spend is a small, cheap win. Goal check-ins (`CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0`), cross-session inbound (`"crossSessionInbound": "hold"`), prompt suggestions, session recap and `/loop` tasks all re-read the context while the user is idle ([Manage costs](https://code.claude.com/docs/en/costs)).

## Effort, not terse prose, governs output tokens

Output is where the 5.5 generation moved the most money, and effort is the main lever. Fable 5.2, Opus 5.5, Sonnet 5.5 and Haiku 5.5 default to `medium`, and "Opus 5.5 at `medium` is described as matching or exceeding Opus 5 at `high`". `max` "can overthink" ([Model config](https://code.claude.com/docs/en/model-config)). `MAX_THINKING_TOKENS` is ignored on adaptive models, and display settings such as `showThinkingSummaries` do not change what is billed ([Env vars](https://code.claude.com/docs/en/env-vars); [Model config](https://code.claude.com/docs/en/model-config)). The resolution order holds a trap. `CLAUDE_CODE_EFFORT_LEVEL` beats every other source, including per-agent frontmatter. Since v2.1.280, `effortLevel` in *user* settings is ignored by Opus 5.5 and later, though project and local settings still apply it ([Model config](https://code.claude.com/docs/en/model-config)). adtok's effort policy should therefore set `effort:` in agent frontmatter (`low` for read-only research agents) and refuse to set the env var. It should lint for `max` (which `/usage` now warns about) and for a global env override. Anthropic's own measurements, covered in the routing research, found that escalating on failure (Opus 5.5 at `low`, failures re-run at `high`) solved about 97% of tasks for $0.17 each, against 95.3% for $0.29 with everything at `high` ([Optimizing for cost and intelligence](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)).

Brevity styles help less than their marketing says, and a one-liner gets most of the effect. The built-in **Concise** style (v2.1.237+, `"outputStyle": "Concise"`) drops preamble and recap while doing "the engineering work as thoroughly as in the Default style". Switching to it mid-session is cache-safe ([Output styles](https://code.claude.com/docs/en/output-styles)). Caveman's 10-prompt README claims about 65% fewer output tokens, but real-task A/Bs measured about 8.5%. Against a one-line "be concise" instruction, it was only 4% better ([moclaw](https://moclaw.ai/blog/caveman-skill-token-savings); [Towards AI](https://pub.towardsai.net/how-to-make-claude-code-as-cheap-per-task-as-gpt-6-astra-without-talking-like-a-caveman-753366be7a13); [Implicator](https://www.implicator.ai/caveman-claude-code-skill-cuts-output-20-your-bill-barely-notices-2.md)). Heavy brevity skills add about 1,000–1,500 input tokens per turn, which can cancel the saving. Prose styles also cannot touch the tool-call arguments and thinking that make up most output tokens. adtok should offer `Concise` as a toggle, not a default-on layer, and never stack it with a brevity skill. Leave `CLAUDE_CODE_MAX_OUTPUT_TOKENS` alone, because raising it shrinks the window left before auto-compaction ([Env vars](https://code.claude.com/docs/en/env-vars)).

## Measure cost per successful task from deduplicated transcripts

Every other layer depends on measurement, because the evidence says intuition about savings is wrong in both directions. Transcripts live at `~/.claude/projects/<project>/<session>.jsonl`, with subagents under `<session>/subagents/agent-<id>.jsonl` in the same format ([.claude directory](https://code.claude.com/docs/en/claude-directory)). Per-request usage sits in `assistant` records under `message.usage`, including the `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` split. These field names are observed, not documented. One API response is written as several records, so "deduplicate by ID" on (`message.id`, `requestId`) and keep the most complete record. ccusage undercounted one day's output 130,785 against 648,562 before it fixed first-seen dedup ([Agent SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking); [ccusage #888](https://github.com/ryoppippi/ccusage/issues/888)).

The reader has several pitfalls to handle. It must skip `.orphaned-` and `.superseded-` files and exclude `<synthetic>` models. It must sum subagent JSONL rather than trusting the Agent result's `usage`, which is only the last request. It must price reads at 0.05× on Opus and Sonnet 5.5 rather than the 0.1× most tools assume, and use the session's final `cost-state` record for auxiliary calls (web helpers) that leave no assistant records. On this machine, deduplicated sums matched `cost-state` exactly. That record is undocumented, so adtok should treat it as a version-checked cross-check ([.claude directory](https://code.claude.com/docs/en/claude-directory); [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)).

For A/B benchmarks, `claude -p --output-format json` reports `total_cost_usd` and per-model `modelUsage` including subagents. Top-level `usage` counts only the main loop, and resumed runs include earlier spend ([Agent SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking); [Headless](https://code.claude.com/docs/en/headless)). OpenTelemetry (`CLAUDE_CODE_ENABLE_TELEMETRY=1`, `console` or `prometheus` exporters) adds `query_source` (main, subagent or auxiliary) attribution and a `claude_code.tool_result` event with `tool_result_size_bytes` ([Monitoring](https://code.claude.com/docs/en/monitoring-usage)). Telemetry captures tool output *before* PostToolUse hooks run, while the transcript shows what the model received ([Hooks reference](https://code.claude.com/docs/en/hooks)). The gap between the two is a direct, local measure of what adtok's tool layer removed. The benchmark harness should report cost per successful task with confidence intervals, plus turns per task and cache-write share, because those are the variables through which savings have reversed.

## Layers interact through one cache and one hook slot

The ensemble's main risk is that the layers undo each other, and the mechanisms are concrete.

**Token reduction is not cost reduction.** Removing tokens that would be read at 0.05× saves little, while adding a turn costs a full read plus output. Every trimming layer therefore needs a size threshold and should be judged in the A/B harness, not by bytes removed ([arXiv 2607.12161](https://arxiv.org/abs/2607.12161)).

**Layers overlap.** A lower compaction window, tool-output trimming and delegating verbose work to subagents all shorten how long large outputs ride along. With a 250K window, much of a trimmed log's saved re-read cost would have disappeared at the next compaction anyway. adtok should measure these layers together.

**Compaction has its own costs.** Each compaction rebuilds project context even when the files are unchanged, which raises the value of a trimmed prefix ([Prompt caching in Claude Code](https://code.claude.com/docs/en/prompt-caching)). It also drops path-scoped rules until they are re-triggered. A window set too low invites the "thrashing" stop when one large output refills context ([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)).

**Routing interacts with the cache in specific ways.** Model switches are the costliest invalidator. Forks lose their free cache read if routed to another model. Explore and Plan start without CLAUDE.md, so prefix trimming matters less for them. Haiku agents need the 100K window cap to stay in the cheap price tier.

**Hooks compete for a single slot.** Multiple `updatedInput` producers race, so adtok must register **one dispatcher per hook event**. The dispatcher runs the enabled layers in order, composes a single merged input, and emits one decision. The conflict check should refuse to install a tool rewriter when it finds another (RTK or a user hook) on the same matcher ([#83353](https://github.com/anthropics/claude-code/issues/83353)).

**Advisory text accumulates.** UserPromptSubmit `additionalContext` sits next to the prompt and stays in history, so each tier hint is re-read on every later turn. Hints should stay a few dozen tokens ([Hooks reference](https://code.claude.com/docs/en/hooks)).

**Global switches break other layers.** `CLAUDE_CODE_EFFORT_LEVEL` silently flattens per-agent effort. `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` silently disables tool search, context editing and effort cache-safety. A gateway that strips betas or `cache_control` breaks the cache layer for everyone downstream.

## Ship six layers behind one dispatcher

The shortlist below orders features by certainty of saving times ease of testing. Measurement comes first because it is the gate for the rest. The static, cache-safe layers follow, and the layers with documented quality risk come last and default off.

| Priority | Layer | Feature (testable behaviour) | Proposed toggle | Default |
|---|---|---|---|---|
| 1 | measure | Deduplicated transcript ledger: main and subagent, 5m/1h split, 5.5 read rates, `cost-state` cross-check; golden-file tests on fixture JSONL | `measure.ledger` | on |
| 2 | measure | A/B harness reporting cost per successful task, turns and cache-write share via `claude -p --output-format json` | `measure.ab` | on (bench only) |
| 3 | safety | Conflict check: one dispatcher per event, foreign rewriters, `CLAUDE_CODE_EFFORT_LEVEL`, `DISABLE_EXPERIMENTAL_BETAS`, gateway beta forwarding | `safety.conflicts` | on |
| 4 | prefix | Offline prefix audit with token counts and the lint rules above, including adtok's own injections | `prefix.audit` | on |
| 5 | cache | Static invalidator lint (`opusplan`, skill `model:`, tool search off, `FORCE_PROMPT_CACHING_5M`, volatile CLAUDE.md) | `cache.lint` | on |
| 6 | cache | Cache-miss attribution per turn (model/version/TTL gap/compaction) | `cache.misses` | on |
| 7 | cache | TTL advisor re-pricing real sessions under 5m vs 1h | `cache.ttl_advisor` | on (report only) |
| 8 | context | Lower compaction window via `autoCompactWindow`; Haiku agents get `autoCompactWindow: 100000` | `context.compact_window` (e.g. `250000`) | on |
| 9 | context | PreCompact preserve list plus PostCompact handoff note; `/clear` advice for large-context topic shifts | `context.handoff` | on |
| 10 | context | Background-spend quieting (goal check-ins, cross-session hold) | `context.quiet_background` | off |
| 11 | output | Effort policy: per-agent `effort:` frontmatter, lint `max` and env override, escalate-on-failure helper for benchmarks | `output.effort_policy` | on |
| 12 | prefix | Skill listing trim via `skillOverrides` name-only for rarely used skills | `prefix.skills` | off (suggest) |
| 13 | tools | Allowlisted test/build wrapper: tee log, tail plus errors plus path, original exit code, merged input, skipped in auto mode | `tools.test_output` | off until A/B |
| 14 | tools | `bashOutputMaxChars` and `MAX_MCP_OUTPUT_TOKENS` caps | `tools.output_caps` | off |
| 15 | tools | Read/Grep guard: `limit` above N lines, strip `allow_large`, Grep `head_limit` | `tools.read_guard` | off |
| 16 | output | Built-in `Concise` output style | `output.concise` | off |

Each feature maps to a deterministic test. The audit and lints run on fixture repos. The ledger runs on recorded JSONL with known totals. The hook dispatcher is tested by feeding it recorded hook payloads and asserting the merged `updatedInput` keeps every original field. The wrapper is tested by asserting exit-code preservation and the "full log at PATH" line. The A/B harness is the only end-to-end proof that a toggle saves money. It should gate any layer from off to on by default.

## Conclusion

The research changes what "token optimization" should mean for adtok. On the current price sheet, the expensive events are rewrites of the cache and output the model chooses to generate. Re-reading cached tokens is cheap. So the most valuable toolkit features are guards and audits that prevent rebuilds, cap growth and keep effort sane, more than compressors. These are also the features that are cheapest to build and easiest to prove. Tool-output trimming is worth shipping only as a narrow, threshold-gated, failure-preserving wrapper that the A/B harness has to justify, because every public attempt to do it broadly saved tokens and lost money.

The ensemble framing matters more than any single technique. The layers share one cache, one hook slot per event and one budget of turns, so their savings are not additive and their failures compound. A single dispatcher, a conflict check and a ledger that prices sessions the way Claude Code does are what set adtok apart from yet another collection of tips. They let it answer the question no built-in surface answers today: after every toggle, did cost per successful task actually go down?
